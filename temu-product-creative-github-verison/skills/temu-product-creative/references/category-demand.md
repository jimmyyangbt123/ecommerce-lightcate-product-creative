# 类目需求组件：先决定讲什么，再决定几张图

完整方案/制作在用户选类目后、推荐图数前必读。调用指执行本组件，不假设存在额外插件或API。对每个已选类目×实际SKU分别分析；只改一条文案时按该项缩小。类目决定关注点，商品证据决定能承诺什么。输出可检查的决策摘要，不输出内部逐步思维。

## 输入与返回

为已选方向建立暂定L-ID（用于追溯，不代表数量/制作已批准），确认后沿用。输入：用户已选主/辅方向及状态、实际SKU/发货、F事实及缺口、市场/语言、已有图数/套数约束、多链接意向。SKU归属或多链接类型未明且会改变判断时先按 intake 补问；不把其他款参数当输入。

面向商家的回复按以下顺序组织：①消费者/任务/时机摘要；②需求—利益—证据简表；③有影响主利益的缺口则集中问并停下等答；④缺口已解决时给逐图必要性表，随后总结推荐图数/取舍并请求确认。尚未定图数时，回复开头先讲任务与购买理由，推荐数量只在图位表后出现；用户已经指定的数量可以开头复述为已知约束。字段没有依据时明示假设/未知，不能用空模板或泛泛“户外、方便、高级”代替内容。

## 1. 先建立消费者与任务

用一至三句回答：什么人，在什么环境与时机，正在做什么，遇到什么不便，希望得到什么结果。消费者按活动/约束描述，不凭空指定年龄、收入或人口占比。可提出合理使用假设并标“首测假设”；商家已有定位优先，不把推测写成调研结论。

再列该任务最关键的购买疑问，区分适配门槛、购买理由、辅助体验与选购避错。排序看任务后果、相关性、现有证据与表达价值；无经营数据给简短理由，不造热度/转化/权重分数。

## 2. 需求—利益—证据表（必填）

每个方向通常保留前三项核心疑问，实际不足则不凑；内部用P1等表示痛点、B1等表示利益，均带L-ID/版本避免串套。

`痛点P/优先级与理由｜消费者任务/不便后果｜购买疑问｜本SKU事实F或缺口｜特征如何帮助任务｜可用利益B/候选短词｜证明方式/场景｜成立条件与禁用扩张`。

按“任务→痛点→商品事实→作用关系→买家利益→可见证明”组织。只有参数而没有作用关系，不能直接升级主卖点；只有类目需求而没有商品支持，则保留待核。不能把收到的所有参数挨个放大或每个零件各占一张。

工地照明可能首先担心持续作业中断，需要调查续航、供电/换电和工作面；户外运动可能首先担心携行负担，需要调查重量、收纳与固定。**这是调查起点，不是固定答案**：短时维修、长途徒步、家庭露营可有不同优先级。容量不是续航，类目不是轻量证据；未确认时不能称“持久/轻巧”。

## 3. 由需求驱动追问

先分开三层：
- **卖点方向**：由Agent根据类目主动判断，例如持续作业、轻松部署、随行照明、营地共享；无需让商家确认“是否希望突出某卖点”。方向可以先提出，不因缺一个参数就停止其他创意。
- **营销表达**：Agent在真实用途内创作购买理由、生活场景、情绪短词和视觉故事。无需逐句向商家求证，不要求每句利益或情绪文案都附数字；以合理作用关系支撑即可。
- **商品能力/性能**：核实实际续航与档位/条件、防水等级、重量、尺寸、接口、模式等。具体数字和“长续航、超轻、全天候”等隐含能力承诺都需依据；叫作卖点不能豁免真实性。

正确问法是“为判断持续作业方向能承诺到什么程度，请提供各档续航及条件”，而非“你想不想突出续航、想写什么卖点”。性能缺口只暂停依赖该能力的承诺/图位，其余用途、利益和场景继续推演；按 intake 解决缺口及完成开工确认后才制作。

对未决项先判断：是否会改变适配、主利益、证明场景或图数？会则说明影响，再只问对应事实/真实使用条件。例：“这个方向准备解决长时间作业中断，是否有不同档位的续航与条件？没有则本次不做续航主张，改讲已确认的供电操作。”不能只因有电池就继续泛问全部规格。

每轮至多三组有关联问题；已回答/明确未知或不用的字段沿用。商家只回答事实、真实受众与业务选择，不要求他自己写痛点、卖点或分镜。Agent先给推荐判断；可问“这次更贴近哪种实际使用？”来消除会改变策略的歧义。

图数尚未确认时，先完成必要补问再给图位建议；不得一边把续航作为待核，一边按“长续航图”锁定数量。明确未知后移除依赖该性能的文案/图标/场景，以有据利益重排。已给完整答案则直接进入建议，不人为拉长轮次。

## 4. 场景想象与事实边界

为每项有据利益提出两个不同的活动/部署候选，再选最清楚的证明方式；这是语义候选，不是提前画完整分镜。按商品可用动作变化人、时机、对象、摆放和过程；非所有商品都要人物。

允许在真实结构与已知适配内创造情境，例如手作架从“整齐静物”扩展为制作中取胶带、完成后分类归位。露营灯可探索携行、帐篷内悬挂、营地整理、同款多灯空间布置，不自动只做喝茶桌面。多件演示仍按 images/visual-strategy 明示实际发货数量，不虚构连线或配件。

可创作的是活动、场景、叙事、镜头和版式；不可创作的是规格、材质、性能、模式、认证、兼容、包内数量与不存在的部件。效果图不是性能测试；雨景也会传达防护承诺。事实可靠不要求构图保守，创意大胆不允许功能失真。

## 5. 逐图必要性与图数建议（用户可见）

先覆盖核心购买疑问，再选展示手段；以足够解释和证明的最小集合为推荐，不默认6/7/8张，不宣称某图数已被证明转化最佳。每个候选图位一行：

`图号/作用｜回答的买家疑问/P与B｜具体内容及事实F｜为什么要独立存在｜相对其他图新增什么｜合并/删除取舍`。

图位可用于识别、任务利益、动作/结构证明、选购避错；不是固定的功能/外观/尺寸/包装各一张。参数、尺寸与到货清单可并入相关图，只有明确阅读/选购价值才单列。四宫格算一张成品，各格须有独立内容，不靠格数撑图数。

做删除测试：“去掉这张，会丢失哪个购买答案或必要证明？”无实质损失则删除或合并。允许同一利益的场景总览与部件特写并存，但须明确从使用结果到操作/结构证明的增量；同卖点换背景、天气、同义口号不算新增内容。核心痛点至少有可交付的准确解释/证明，不能被外观和参数占满轮播。

商家已指定数量：先在该约束内编排，不重复问已答数量；若内容不足或确实需要更多图，给具体保留/合并/补证方案与影响，等其接受变更，不能静默少交或编造用途。多方向独立推荐数量，不自动三套都8张；用户选三套各8张则按24图执行。

给一句推荐总数及取舍，问是否采用；随后开工单可引用此表编号，无须再粘贴同一长表。开工后详细分镜承接已确认的图位理由，不另起不一致的方案。

## 类目调查起点与来源

| 类别/任务 | 优先调查的问题 | 可用证明 |
|---|---|---|
| 作业照明 | 中断、工作面、方向/固定、供电和环境 | 有条件性能资料、真实操作 |
| 户外便携照明 | 携行负担、收纳、部署、供电与防护 | 重量/尺寸、动作、适配资料 |
| 装饰/桌边照明 | 空间搭配、氛围、放置/安装、操作 | 场景关系、光色、细节 |
| 收纳/家居 | 找取/归位、物品适配、占地与稳定 | 分类取放、尺寸、承重资料 |
| 厨房/工具 | 任务步骤、适配、操作与清理 | 真实操作和已确认条件 |
| 服饰/配件 | 穿搭场合、版型尺码、调整、材质 | 穿戴/细节、尺码与成分资料 |
| 电子/安装用品 | 接口、型号兼容、供电、安装与操作 | 准确部件和对应步骤 |

这些是问题库，不是自动卖点。照明查 [用户类目表](categories.md)，其他品类只用用户给定或实际核实的来源；无树给通用任务并标路径待映射。节点存在不等于当前后台可刊登。
