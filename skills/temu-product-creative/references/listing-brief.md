# 类目前置与逐链接创意合同

这是完整制作和多套方案的开工前置，不是交付后附上的建议。认货后先给类目建议，用户选定后执行 category-demand 需求分析；完整分镜或生图前锁合同。商品尚无法识别时先补问，不能在认货前凭空确定类目。只改一条文案或诊断旧图时只核相关定位，不强迫完整矩阵。

## 第一份用户可见结果：主类目＋辅类目建议

识货后、完整方案前先给候选简表：`角色｜候选完整路径或通用品类名｜买家任务｜商品适配依据｜推荐理由｜状态/缺口`。

- 主类目：首推一项作为建议，等待用户选择制作方向，不只写“照明/家居”等上位概念。
- 辅类目：最多两项有独立任务的候选；没有合理项明确无，不凑数量。辅助候选不是同链接后台的第二个分类，也不是已经批准的第二个listing。
- 类目状态：用户树内匹配、后台已确认或通用方向待映射，分别标记。存在节点不证明当前站点可发布。照明查用户树，其他品类不用照明路径。
- 已明确指定且适配的主类目直接沿用，仍简要给相关辅助机会；不适配时说明并推荐，不盲从错误归属。

按 [对话关卡](intake.md) 等用户明确选择类目；再调用 category-demand，展示需求/证据和逐图必要性，才建议图数并确认规模、多链接类型与开工单。不能展示首推后自行继续。身份已知但无官方类目树时，用户确认通用任务后可制作非发布草案，标“路径待映射”；不能伪造ID或宣称可直接刊登。核心用途/适配仍不明时，只暂停依赖它的方案。

## 为每个制作方案建立 L-ID 合同

L1/L2是内部方案号，不是平台listing ID；同SKU可有多套创意，不因此多出实物SKU或发布资格。每条实际制作方案均填写：

| 字段 | 必填内容 |
|---|---|
| L-ID与版本 | 如L1-v1；用户改类目/任务则升版本 |
| 类目与状态 | 完整路径及来源，或通用方向与待映射状态 |
| 类目选择来源/开工状态 | 用户选择原话与确认单版本；缺确认不制作 |
| 套数与每套图数 | 本L-ID总张数、其他L-ID数量、展示图位合计和独立素材数 |
| 差异类型/实际款 | 同款创意/真实差异/开发；真实值、基准、差幅与适用条件 |
| 独立标题策略 | 类目品类词、买家任务/搜索意图、主推已确认特征、SKU/数量边界、最终标题及中文核对 |
| 站点/买家语言/规格 | 依交付范围锁定；未指定买家语言时通用英文，业务说明中文 |
| 实际SKU/发货 | 型号、全部真实可选主商品件数、配件、公共与独有事实ID；准确数量标签、标题前缀与主图顶部文案（按quantity） |
| 消费者与使用时机 | 按真实活动/约束描述，区分商家事实与首测假设，不编人口属性 |
| 核心买家任务 | 人/环境/时机/动作、要解决的问题及期望结果 |
| 优先痛点与利益证据 | P/B-ID、该类目优先级理由、F事实到利益的作用关系、证据缺口与问答结果；不足三项不凑 |
| 主销售锚点 | 准确短词及事实ID；列辅助利益与证明方式 |
| 场景边界 | 核心场景、可用支撑场景、不用于本套的方向及原因 |
| 表达方向 | 所要展示的利益/操作关系、证据镜头、版式与文字重心 |
| 标题与图位必要性 | 每图回答的问题、独立存在理由、相对其他图的信息增量、合并/删除取舍；推荐数/用户确认数与依据、复用清单 |
| 发布/制作状态 | 创意草案、制作中、待验等；刊登资格另列 |

没有合同、需求与图位必要性记录、用户选择/开工确认未完成或缺核心任务/锚点，不进入生成。缺参数时省略主张，不阻止有据的合同内容。两方向比较在该合同的任务边界内进行，不能比较着比较着换了目标类目。

## 场景与卖点必须受 L-ID 约束

所有标题、短词、分镜、提示词和产物都带L-ID、版本、SKU与事实引用。生成指令写入当前类目/任务、锚点、场景边界；不能只附商品事实让模型自由挑用途。

同一套的封面、前段主要利益图、场景拼图优先服务核心任务。纯规格、清单图可以中性复用。其他任务只有明确作为次要支撑且不会稀释当前定位时进入后段；不能为凑四宫格把不同候选类目的用途随便拼在一起。

示例：若L1锁定营地照明，组合图可围绕营地桌面、帐篷内合适挂点、营地整理等已证实用法；不默认把衣柜/车库放入核心组合。若L2锁定家庭备用，则突出室内取用、操作和供电等实际任务，防水参数有据也不自动成为最大标题。此例不要求所有灯都适用这些任务。

## 按用户选择的多链接分支判差异

先完成 intake 的多链接类型对话，不能把所有分支强制套同一种差异。

- **同SKU创意分支**：共享同SKU真实事实，两条方案在类目任务/痛点、锚点、场景/操作、标题重心和核心图表达上要有实质区别。只换名称/颜色/标题词不算创意差异。任务相同时可建议合并或同链接测试，但须用户接受，不能擅减套数。
- **真实不同款分支**：各SKU使用自己的容量、尺寸、配置和发货事实。任务可以相同；真实规格差异本身可以影响选购，不为制造不同任务而乱换类目，也不因任务相同自动合并。可复用的仅是两款确实相同的信息/视觉元素。
- **开发/混合分支**：真实款与开发目标分开；目标仅做内部开发提案，实际销售套图不能引用目标值。每个L-ID单独注明分支和可执行状态。

公共清单/规格图在确实适用时复用，核心图按各合同制作。任何套数、图数、类目或SKU合并均是建议，取得受影响范围的新确认后执行；不能靠改参数或套话制造区别。

## 更改与验收

用户更改类目、图数/套数、差异类型或核心任务：更新主辅建议、相应合同版本，重跑受影响的需求/证据和图位必要性，重排卖点，检查标题、核心图和场景拼图；失配项退回待修，其余可复用，并重新确认受影响的开工单范围。不能只改类目文字而交付旧套图。

验收逐项问：这张图回答哪个L-ID的哪项痛点？事实能支撑吗？镜头有可见证明吗？核心图是否串入别的合同任务？多方案是否真正不同？先做合同一致性，再做画面质量。无能力看图时只验文字映射，保留视觉待验。
